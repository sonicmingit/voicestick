# 自定义按键（Windows / StickS3 0.4.0）

在 Windows 托盘打开「设置 → 按键与快捷键…」，修改后先点「确定」，再在设置窗口点「保存」。设备需升级到包含手势协议的 0.4.0 固件。旧固件保留主键录音、侧键发送的原有操作；仅安装新版客户端不会获得硬件双击和长按。

| 手势 | 默认功能 |
| --- | --- |
| 主键单击 | 确认发送已填入的文字 |
| 主键双击 | 不执行操作 |
| 主键长按 | 按住录音，松开结束 |
| 侧键单击 | 撤销 Ctrl+Z |
| 侧键双击 | 重做 Ctrl+Y |
| 侧键长按 | 粘贴 Ctrl+V |

主键长按说话，松开后识别结果直接填入当前输入框；可以手工修改，再单击主键发送。输入完成后悬浮窗立即收起，不弹成功提示。确认发送仅对同一设备最近一次成功填入有效，且要求仍处于原来的顶层窗口。切换聊天对象或同窗口内的输入框时仍需自行检查焦点。

上表是「恢复默认」的方案，实际按键以你保存的配置为准。例如希望侧键单击粘贴、长按撤销，可分别选择「粘贴 Ctrl+V」和「撤销 Ctrl+Z」，其余手势继续独立配置。

## 可选功能

六个手势都能选择不执行、确认发送、开始／结束录音、取消当前识别、重新填入上次识别、复制、剪切、粘贴、撤销、重做、全选、Enter、Shift+Enter、Esc、自定义快捷键。「按住录音，松开结束」仅允许绑定到长按。开始／结束录音可绑定到单击、双击或长按，再次触发任一开始／结束录音动作即可结束。

自定义快捷键可点击「录制」，按下 Ctrl、Shift、Alt 等修饰键与普通键，也可直接输入 `Ctrl+Shift+V`。手动输入支持 Win 修饰键，字母、数字、F1–F24、方向键、Home、End、PageUp、PageDown、Enter、Esc、Tab、Space、Backspace、Delete；系统保留组合键可能无法录制或执行。普通快捷键在当前前台窗口执行；按键注入被 Windows 权限限制或物理修饰键未松开时，不会执行。

「确认发送」与「Enter」不同：前者检查待发送记录、设备和原窗口，后者向当前窗口发送普通回车。目标软件用 Ctrl+Enter 发送时，可自行绑定自定义快捷键；这种普通快捷键不带待发送窗口检查。

「粘贴」使用当前剪贴板；「重新填入上次识别」使用客户端内存中保存的最近识别结果，并更新剪贴板。最近识别结果不跨客户端重启保存。撤销、重做由目标软件实现，撤销作用于该软件最近一次编辑，不保证只撤销语音文字，也不能撤回已经发出的消息。重做默认 Ctrl+Y，可自定义成软件需要的 Ctrl+Shift+Z。

## 手势判定与预设

长按阈值默认 500 毫秒，可设 500–1500 毫秒；双击间隔默认 300 毫秒，可设 150–500 毫秒。长按只触发一次，松开不再触发单击；长按绑定为「不执行操作」时，保持不执行，也不会补发单击。绑定了双击时，单击会等待双击间隔；双击绑定为「不执行操作」时，单击松开立即执行，因此此时快速按两次会执行两次单击。一次短按后再长按，分别视为单击和长按。

按住录音会从物理按下时开始缓存音频，达到长按阈值才提交识别；短按的临时音频直接丢弃。麦克风仍有硬件启动时间，可以在按下后开始说话，并根据习惯调整长按阈值。识别期间普通编辑快捷键暂停响应，「取消当前识别」和录音控制仍可使用。取消识别会丢弃当前录音／识别结果，不删除已经填进目标软件的文字。

在预设框输入名称，点击「保存为预设」，即可保存当前六个动作及时间参数；选择已有名称并点击「载入预设」可切换。「恢复默认」恢复上表。预设随外层设置的「保存」写入 `%APPDATA%\VoiceStick\config.toml`；取消外层设置会放弃本轮修改。

设置保存在客户端，每次连接同步到设备；设备重连其他旧客户端时恢复旧协议。关闭「启用自定义按键」后，使用原先的「按住／点击录音」和「旧固件发送」选项。

## 固件与验证

本地固件构建使用 ESP-IDF 5.5 系列、目标 `esp32s3`，分区与原项目相同。合并固件用于 USB 刷写，OTA 文件只包含应用镜像。先升级客户端，再刷写配套固件并重连。安装客户端不会自动刷写硬件。

可在 ESP-IDF PowerShell 环境运行 `scripts/build-firmware-local.ps1` 生成合并镜像、OTA 镜像和校验文件。先用 `python -m serial.tools.list_ports -v` 查看串口，再用 `python -m esptool --chip esp32s3 --port COM9 chip_id` 核对芯片。以下 COM9 仅为本次实机端口，应替换为实际探测到的目标端口，不要根据旧记录选择其他串口。

对已经装好 esptool 的环境，完整合并镜像的 USB 刷写示例为：

```powershell
python -m esptool --chip esp32s3 --port COM9 --baud 460800 write_flash 0x0 build/firmware-local/voicestick-sticks3-merged-0.4.0.bin
```

合并镜像会覆盖对应地址内的启动区、分区信息和数据，适合完整安装；它与本次保留旧应用、只向空闲 OTA 分区写入应用镜像的升级方式不同。选择 OTA 分区及切换启动前，须核对设备现有分区表，不要直接把本机分区地址套到其他设备。

USB 读取无进展、下载报错或出现「配置描述符请求失败」时，先停止失败的传输，重新确认设备连接并按硬件说明复位或进入下载模式。本次通过 ROM 模式、小数据包和发送节流完成升级；没有确认 USB 异常根因。刷写过程详见 [开发日志](开发日志.md)。

## 验证记录

2026-10-19，Windows 0.4.0 与 StickS3 0.4.0 已完成真机连接：BLE 返回固件版本 `0.4.0` 和 `button_gestures: 1`，客户端收到 `buttons_ready` 配置确认；用户随后实际测试并反馈「测试没问题」。两组 Windows 自动测试、固件构建和安装包内容校验均已通过。

本次仍记录了 Windows USB 串口识别异常，未将其标记为已修复。上述实测对应当时保存的按键配置，不代表已遍历全部快捷键及目标软件。更改映射后，可重点检查：短按不录音、长按开头保留、双击不夹带单击、长按快捷键只执行一次、撤销／重做符合目标软件习惯，以及切换窗口后确认发送不误发。
