# 开发日志

## 2026-10-19 · 0.4.0 自定义按键与真机验证

Windows 客户端与 StickS3 固件版本均升级为 `0.4.0`。本次完成从手势识别、客户端配置、安装包构建到硬件刷写的完整流程，用户随后完成实际操作测试，反馈「测试没问题」。

### 功能变更

- 主键、侧键分别支持单击、双击、长按，共六个可配置手势。
- 默认主键单击确认发送、双击无操作、长按录音；侧键单击撤销、双击重做、长按粘贴。用户保存的自定义映射优先于默认方案。
- 新增「设置 → 按键与快捷键…」，提供动作选择、快捷键录制、时间参数、命名预设和恢复默认。
- 动作包括确认发送、按住录音、切换录音、取消识别、重新填入上次识别、复制、剪切、粘贴、撤销、重做、全选、Enter、Shift+Enter、Esc 和自定义组合键。
- 识别完成后立即填入目标输入框，收起悬浮窗；保留 0.3.6 去掉输入完成提示框的行为。确认发送检查同一设备和原顶层窗口，每次填入只确认一次。
- 长按抑制单击，双击抑制对应单击，长按快捷键只执行一次。双击未绑定时，短按松开立即触发。按住录音从物理按下时预缓存音频，短按缓存不上传 ASR。
- 手势配置与预设写入客户端配置文件，设备连接后同步。旧固件或关闭自定义按键时，继续使用原有交互。

### 实现与修复

- 固件增加可独立测试的手势状态机，支持配置替换、断连及取消时清理待判定手势和录音。
- BLE 新增 `button_gestures: 1` 能力声明、配置版本与 `buttons_ready` 确认；客户端忽略旧版本及不匹配的设备事件。
- 修复设备信息早于音频订阅就绪到达时，按键配置无法同步的问题；控制写入按设备串行发送。
- 录音缓存增加提交／丢弃流程；仅在确认录音手势后开始传输。空闲时不轮询手势，短按丢弃缓存后恢复较慢的 BLE 连接间隔。
- 统一快捷键注入及异常释放处理，物理修饰键按住时不叠加注入。录制快捷键时拦截后续字符／粘贴消息，避免 Ctrl+V 把剪贴板内容填进快捷键框。
- 设置窗口每次打开使用最新配置，取消外层设置后不保留本轮按键草稿。
- 增加本地固件构建脚本、Windows 打包说明、硬件位置说明及中文参考图。

### 本次刷写与实测

1. 根据 USB 标识和芯片探测确认目标为 ESP32-S3-PICO-1，内置 8 MB Flash、8 MB PSRAM。本次实际端口为 COM9，未刷写 COM6；端口号不是固定配置。
2. 保存原启动区、分区表及 OTA 选择信息。完整 8 MB Flash 读取未完成，不能将本次记录当作完整 Flash 备份。
3. 确认原 0.3.2 在 OTA_0（`0x10000`）运行，将 0.4.0 应用写入 OTA_1（`0x310000`），保留原应用。
4. 常规辅助下载及连续大包传输不稳定，最终通过 esptool ROM 写入、256 字节数据包和 10 毫秒发送间隔完成写入；设备端哈希校验通过后才切换 OTA 启动选择。
5. 用户重新插拔 USB 并按电源／复位键后，确认屏幕正常亮起。
6. 通过 BLE 实际读取到 `firmware_version: "0.4.0"`、`button_gestures: 1`；Windows 0.4.0 客户端重连后收到 `buttons_ready`，配置版本为 1。
7. 用户完成实际操作测试，反馈「测试没问题」。这属于当前配置的实测结果，本轮没有逐项记录所有快捷键和第三方软件组合。

刷写时的启动区备份、OTA 选择备份和诊断记录保存在本机 `build/firmware-backups/`，该目录不纳入 Git。原 0.3.2 应用保留在 OTA_0，后续覆盖该分区前仍可用于回退。

### 已知问题

- 本次 Windows 曾报告 USB「配置描述符请求失败」，未确认 USB 串口异常已消除。BLE 版本读取、客户端连接与按键配置同步已验证成功，用户实测通过。
- USB 异常的根因尚未确定，不能归结为已修复的固件问题。再次刷机应重新确认设备与串口；必要时按官方硬件说明进入下载模式。
- 确认发送检查到顶层窗口，同一窗口内切换聊天对象或输入框仍需保持正确焦点。撤销／重做由目标软件决定，不等同于撤回已发送消息。
