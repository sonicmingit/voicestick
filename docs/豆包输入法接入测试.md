# 豆包输入法接入测试

本功能为开发分支 `codex/doubao-input-integration` 的实验功能。Windows 客户端与配套 HID 固件必须一起使用；当前不能把编译和单元测试通过表述为真机语音输入通过。

## 原理

```text
StickS3 麦克风 → Opus → 自定义 BLE 服务 → Windows Opus 解码
    → WASAPI → VB-CABLE 播放端 → CABLE Output → 豆包输入法 → 当前输入框

Windows 客户端 → BLE 控制指令 → StickS3 HID 键盘服务 → 语音快捷键按下／释放
```

已有的主键／侧键六种手势继续负责动作分配。新增的标准 HID 键盘服务仅负责语音键，不把所有自定义动作改成硬件按键。HID 与音频、控制、OTA 共用设备的 BLE 连接。

Windows 通过公开 TSF 接口启用豆包；音频交给用户选择的虚拟声卡，不切换系统默认音频设备。没有匹配的通道时，在按下硬件语音键之前失败。程序不读取豆包私有配置、内存、账号凭据或内部语音协议，也不读取豆包生成的文字。

## 使用步骤

1. 退出正在运行的 VoiceStick，保留原版以便回退。
2. 安装 [VB-CABLE](https://vb-audio.com/Cable/)，按驱动安装程序要求处理 Windows 授权和重启。
3. 给设备安装本分支生成的配套固件。USB 合并镜像写入 `0x0`；OTA 镜像只能写入应用 OTA 分区，不能当作 USB 合并镜像使用。
4. 在 Windows 蓝牙设置中配对 `VS-XXXX`，让 Windows 加载其键盘服务。旧配对可能缓存旧服务；如果系统未识别新增键盘服务，需要用户移除该设备的旧配对并重新配对。VoiceStick 内部的设备列表不等于 Windows HID 配对。
5. 启动本分支的客户端，在设置的“识别服务”选择“豆包输入法（测试）”，选择 VB-CABLE 播放端并保存。
6. 豆包设置中，麦克风选择 `CABLE Output`。VoiceStick 的“语音快捷键”必须与豆包设置一致；本分支默认左 Ctrl＋左 Win，也可选右 Alt。在目标输入框切到豆包输入法并确认网络可用。
7. 用已配置的录音手势说话。松开后等待豆包出字，再按配置的确认键发送。默认的 `confirm_send` 在此模式中向当前输入框发送一次回车，不会判断豆包是否已完成识别。

## 会话和失败处理

- 客户端收到 `record_start` 或兼容的主键按下事件后准备音频、启用豆包并请求 HID 按下。只有收到设备确认且观察到豆包语音窗口后，才向虚拟麦克风播放缓存音频。
- 长按阈值期间的固件预录音可以继续使用；客户端把积压音频按真实采样速率播放。
- `record_stop`／主键释放只开始等待音频 END，不丢弃尾部音频。END 后等待音频队列和 WASAPI padding 排空，再请求释放语音快捷键，并等待设备确认。
- 缺少 END、音频积压、解码错误、断连、配置切换和退出都会停止该会话。取消请求尝试先通过 HID 发送 Escape，再释放语音快捷键；已经由豆包写入输入框的文字由输入法管理，VoiceStick 不负责撤回。
- 客户端每 500 ms 续期语音键；固件的 2 秒租约和断连清理用于避免修饰键长期保持按下。旧会话的释放指令不能释放新会话的按键。
- HID 按下要求加密连接和 Windows 的输入报告订阅；没有配对／未订阅时返回失败，不把 BLE 写入成功当作语音启动成功。
- 日志仅记录阶段和结果，不记录音频、文字、蓝牙地址或音频端点 ID。

## 当前功能边界

- 识别由豆包输入法负责；本模式不使用 VoiceStick 的 ASR API 密钥。
- 原有 ASR 服务仍可选择。字幕、翻译、识别文字恢复和 ASR 热词不适用于豆包模式；字幕／翻译配置会阻止启动本模式的录音。
- 豆包语音窗口通过公开 Windows 窗口类 `OimeVoiceWaveWindow` 检查。豆包版本变更可能需要更新该判据，必须用物理按键对照复核。
- 尚未完成新 HID 服务与真实 Windows 配对、首次开麦、音频回环、长按预录和取消行为的端到端验收。

## 开发与复核

Windows 构建：

```powershell
cmake -S desktop/windows -B desktop/windows/build-local-x64 -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DVOICESTICK_ENABLE_APP_UPDATES=OFF
cmake --build desktop/windows/build-local-x64 --parallel 4
ctest --test-dir desktop/windows/build-local-x64 --output-on-failure
```

`voicestick_ime_probe.exe --self-test` 验证 16 kHz 单声道、60 ms、20 kbit/s Opus 编码／解码；不打开麦克风。`--list-audio` 只报告匹配的虚拟声卡播放端数量。无参数运行打开独立测试窗口，可选左 Ctrl＋左 Win或右 Alt，用于对比软件模拟与物理键盘；不会发送聊天消息。

`voicestick_ime_native_tests` 验证端点缺失时不会按下硬件语音键，以及取消后迟到的结果不会复活旧会话。核心测试覆盖 END 前的尾部音频、跨设备／跨会话隔离、重复 END、断连取消及固件按键租约。

本机观察（2026-10-19）：豆包输入法 0.9.2.7 已安装，实际快捷键由用户配置为左 Ctrl＋左 Win；未发现 VB-CABLE 播放端。最初右 Alt 阴性测试使用了错误快捷键，不用于判断兼容性。改用左 Ctrl＋左 Win 后，测试程序报告 TSF 激活、模拟按下／释放成功，但仍未观察到豆包语音窗口；用户在同一测试窗口用物理左 Ctrl＋左 Win 长按后，确认语音条出现。此结果支持继续采用设备 HID 路径，但不替代新固件和音频链路验收。

最新自动化验证包含 4 项 CTest 目标：核心会话／配置／固件按键租约、Opus 编解码、原生端点失败及取消回调、按键设置。确切执行结果见测试包内的验证记录。

后续真机验收需覆盖：物理键和 HID 键均能唤起豆包、CABLE 回环有声音、首字／尾字完整、连续录音、长按缓存、短按、取消、切换前台应用、客户端退出与设备断连、重新配对，以及睡眠唤醒后首用。
