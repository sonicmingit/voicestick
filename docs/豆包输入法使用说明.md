# VoiceStick 豆包输入法使用说明（Windows）

Windows 客户端 0.4.3 支持通过设备按键唤起豆包输入法，把 StickS3 麦克风的声音交给豆包识别，并由豆包直接写入当前输入框。界面中的服务名称仍为“豆包输入法（测试）”。此模式无需填写 VoiceStick 的 ASR API Key，使用前需安装豆包输入法、VB-CABLE，并在 Windows 中配对带 HID 键盘服务的设备固件。

## 1. 下载配套文件

从 [0.4.3 Release](https://github.com/sonicmingit/voicestick/releases/tag/windows-v0.4.3) 下载：

| 文件 | 用途 |
| --- | --- |
| `VoiceStick_0.4.3_zh-CN_custom-buttons_x64.msi` | Windows x64 客户端安装包 |
| `VoiceStick_0.4.3_zh-CN_custom-buttons_x64.zip` | 客户端便携包；与 MSI 二选一 |
| `VBCABLE_Driver_Pack45.zip` | VB-CABLE 官方原始驱动包，需单独手动安装 |
| `voicestick-firmware-sticks3-ota-0.4.3.bin` | 支持 OTA 的设备使用的应用固件 |
| `voicestick-firmware-sticks3-merged-0.4.3.bin` | USB 首次烧录的合并固件，偏移 `0x0` |
| `SHA256SUMS.txt` | 上述附件及固件清单的 SHA-256 校验 |

源码仓库根目录也提供同一个 `VBCABLE_Driver_Pack45.zip`。客户端安装包和便携包附带本说明；驱动包作为独立附件分发。豆包输入法请自行从其官方渠道安装，VoiceStick 不包含输入法安装程序。

## 2. 安装客户端与设备固件

1. 从托盘退出旧版 VoiceStick；关闭设置窗口不会退出后台客户端。
2. 安装 MSI，或完整解压便携包后运行其中的 `VoiceStick.exe`。只运行其中一份客户端。
3. 安装本 Release 的 StickS3 固件。已装有配套 HID 开发固件且功能正常的设备，无需为这次客户端连接修复重新刷机。旧的原版固件即使版本号相似，也可能没有 HID 键盘功能。
4. OTA 文件用于应用升级；USB 合并文件用于首次安装，写入地址为 `0x0`。详细步骤见同目录的 [自定义按键使用说明](自定义按键使用说明.md)。
5. 设备屏幕顶部显示 `FW <版本>`；客户端设置底部也显示客户端和已连接设备的固件版本。

客户端沿用 `%APPDATA%\VoiceStick\config.toml`，更新前后保留原有配置和 API Key。

## 3. 安装 VB-CABLE，并重启 Windows

1. 完整解压 `VBCABLE_Driver_Pack45.zip` 到本地文件夹。不要只从 ZIP 中打开单个 EXE。
2. Windows x64 用户右键 `VBCABLE_Setup_x64.exe`，选择“以管理员身份运行”。
3. 点击 `Install Driver`，等待安装完成。若程序提示已安装，先检查系统是否已有下方两个端点，无需反复安装。
4. 安装完成后重启 Windows。这是 [VB-Audio 官方安装要求](https://vb-audio.com/Cable/)。
5. 按 `Win + R`，输入 `mmsys.cpl`，回车打开“声音”。在“播放”页确认有 `CABLE Input (VB-Audio Virtual Cable)`，在“录制”页确认有 `CABLE Output (VB-Audio Virtual Cable)`，且均已启用。

两端名称容易混淆，请按下表选择。普通的 VB-CABLE 会把 Input 收到的声音传到 Output，方向见 [官方说明](https://vb-audio.com/Cable/)。

| 设置位置 | 应选择的设备 | 作用 |
| --- | --- | --- |
| VoiceStick 的音频通道 | `CABLE Input`（播放端） | 接收设备麦克风的声音 |
| 豆包输入法的麦克风 | `CABLE Output`（录制端） | 让豆包听到 VoiceStick 传来的声音 |

使用 CABLE A/B 等多通道版本时，两边选择同一条虚拟线缆。VoiceStick 列表可能显示不止一个匹配的端点，应按名称选中对应通道。

无需把 CABLE 设为 Windows 默认扬声器或默认麦克风；保留自己的耳机、音箱等默认设备。仅使用 API 模式时不需要 VB-CABLE。

## 4. 在 Windows 中配对 VS 设备

1. 暂时从托盘退出 VoiceStick，使设备可被 Windows 搜索到。
2. 唤醒或重启 StickS3，确认屏幕上的 `VS-XXXX` 名称。
3. 打开 Windows“设置 → 蓝牙和设备 → 添加设备 → 蓝牙”（Windows 10 为“蓝牙和其他设备”），选择对应的 `VS-XXXX` 并完成配对。
4. 等待 Windows 加载键盘服务，再启动 VoiceStick。客户端中也需要添加或选择同一设备，等待连接成功。

Windows 的系统配对负责 HID 键盘，VoiceStick 内的设备列表负责客户端连接，两者都要完成。新版客户端会保留系统配对，不会为重连而自动删除配对或重启整台电脑的蓝牙。

若此前旧版客户端删除了配对，退出旧客户端后重新配对一次。只有在升级旧固件后 Windows 仍未识别 HID 键盘服务时，才需要手动移除旧配对、重启设备后重新配对；正常使用和切回 API 时均保留配对。

## 5. 配置豆包输入法

1. 打开豆包输入法并完成它自身要求的初始化，确认网络可用。
2. 在豆包设置中把语音输入的麦克风选为 `CABLE Output (VB-Audio Virtual Cable)`。
3. 设置语音快捷键，例如“长按左 Ctrl + 左 Win”。VoiceStick 也支持“长按右 Alt”，但两边必须选择同一组按键。
4. 在记事本等普通输入框中切换到豆包输入法。先用物理键盘长按已设置的快捷键，确认豆包能弹出语音输入窗口，再松开结束。

此时使用的是虚拟麦克风，物理键盘测试主要确认快捷键能唤起语音窗口；设备声音要在下一步 VoiceStick 开始录音后才会传过来。

## 6. 配置 VoiceStick

1. 打开托盘中的“设置”。
2. “识别服务”选择“豆包输入法（测试）”。
3. 音频通道选择 `CABLE Input (VB-Audio Virtual Cable)`。
4. “语音快捷键”选择与豆包一致的“左 Ctrl + 左 Win”或“右 Alt”。
5. 输出选择当前输入框的“原文”模式；设备若有独立输出配置，也设为原文输入。豆包模式不支持 VoiceStick 的字幕和翻译输出。
6. 保存配置。按键使用默认“主键长按录音”即可；若改过配置，进入“按键与快捷键…”确认对应手势分配为录音。

无需为豆包模式填写火山引擎或 VoiceStick Cloud 的 API Key。之前保存的密钥可以留着，以便切回 API 模式。

## 7. 长按说话与确认发送

1. 打开记事本或目标应用，点击要输入的文字框，并切换到豆包输入法。
2. 长按设备主键并说话。默认约 500 毫秒后触发录音，具体以已保存的长按阈值为准。
3. 此时会同时显示 VoiceStick 的“正在聆听”和豆包语音输入窗口，这是正常现象。
4. 说完松开设备按键。客户端播放完尾部音频后释放语音快捷键，由豆包完成识别并写入当前输入框。
5. 等待文字实际出现，检查后再发送。默认主键单击为 `confirm_send`，在豆包模式中会向当前输入框发送一次回车；客户端无法判断豆包是否已经出字，请勿提前单击。

VoiceStick 不读取豆包生成的文字，豆包负责文字填入和后续编辑。默认侧键的撤销、重做、粘贴仍按用户保存的手势配置执行。

## 8. 切回 API 模式

托盘第一层菜单提供“识别服务：当前服务”入口，展开后可直接选择“豆包输入法（测试）”“火山引擎 API”或“VoiceStick Cloud API”；勾选项表示当前服务。选择后立即生效并保存，继续使用原有录音手势。之前保存的两种 API 密钥、豆包音频通道和语音快捷键都会保留。

第一次使用某个服务时，仍需先在“设置”中完成配置。快速切到 API 需要已保存该服务的 API Key；快速切到豆包需要已保存可用的 VB-CABLE 音频通道，且全局及已配对设备的输出均为当前输入框、原文。配置不完整时会提示原因并保持当前服务。

切换会结束当前录音／识别并丢弃尚未填入的结果，也会停止正在执行的快捷键脚本；已填入的文字保留。保留 Windows 配对即可，不需要卸载 VB-CABLE，也不需要移除 VS 设备。也可继续在“设置”中切换识别服务。

API 模式由 VoiceStick 调用识别接口并粘贴文字，豆包模式由输入法负责识别和填入。豆包模式不使用 VoiceStick 的字幕、翻译、ASR 热词或“恢复上次识别文字”功能。

## 9. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| Windows 搜不到 VS 设备 | 从托盘退出 VoiceStick，唤醒或重启设备后再搜索；已被客户端连接的设备可能不再广播。VB-CABLE 不负责蓝牙搜索。 |
| 客户端能连接，却提示蓝牙键盘未就绪 | 确认已在 Windows 系统中配对，且固件包含 HID；只添加到 VoiceStick 列表不够。升级到 0.4.2，避免旧客户端删除配对。 |
| Windows 已配对，仍提示蓝牙键盘未就绪 | 这不一定是配对丢失，也可能是设备的 HID 键盘通道没有恢复。先重新连接设备；若键盘驱动已启动仍失败，可在 Windows 设备管理器中重新启用该 VS 设备对应的蓝牙 HID 键盘，或请管理员重启该设备的 HID 通道。先保留现有配对。 |
| 系统配对后长按连 API 也没反应 | 使用 0.4.2 或更新版。该版本修复 HID 保持连接、重启客户端后未重新初始化按键的问题；等待设备连接完成后再录音。 |
| 找不到 CABLE 音频通道 | 完整解压并以管理员身份安装 x64 驱动，重启 Windows，检查播放／录制端点是否启用，再重新打开客户端设置。 |
| 豆包未弹出语音窗口 | 在目标输入框切换到豆包；检查两边快捷键一致，并用物理键盘对照。设备需完成系统配对。 |
| 有语音窗口，但没有文字 | 检查 VoiceStick 为 CABLE Input、豆包为同一路 CABLE Output；检查录制端音量、静音、麦克风权限和豆包网络。可在“声音 → 录制”观察设备说话时 CABLE Output 电平是否变化。 |
| 识别来自电脑麦克风 | 豆包仍选中了物理麦克风，改为 CABLE Output。 |
| 只出现 VoiceStick“正在聆听” | 查看后续错误提示；只有豆包窗口也打开后才算唤醒成功。 |
| 提示原文输入或输出不支持 | 把全局及该设备的输出方式设为当前输入框、原文，保存后重试。 |
| 松开后稍等才结束 | 客户端会等待尾部音频播放完成再释放语音键，随后豆包还需完成识别。 |

排查时可查看 `%LOCALAPPDATA%\VoiceStick\VoiceStickApp.log`。连接应收到 `device_info` 和 `buttons_ready`；豆包会话应依次出现 `waiting_for_hardware_key`、`microphone_ready`、`waiting_for_key_release` 和 `closed result=completed`。分享日志前请自行检查是否含有识别内容等个人信息。

## 10. 验证范围与第三方说明

2026-10-21 已在 Windows、VS-5614 和豆包输入法 0.9.2.7 上验证：保持配对重启客户端后，API 长按识别与粘贴恢复；设备 HID 成功唤起豆包语音窗口，松开后完成音频收尾、按键释放和会话结束，用户确认语音窗口出现。出字准确度、音频首尾完整性及长时间稳定性仍需继续实测。技术记录见源码仓库的 [豆包输入法接入测试](https://github.com/sonicmingit/voicestick/blob/windows-v0.4.2/docs/豆包输入法接入测试.md)。
