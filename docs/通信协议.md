# Voice Stick 通信协议

本文描述当前固件与 macOS 桌面应用实现的通信协议。

## 设计目标

- 将 StickS3 的按键录音以低延迟传输到 macOS。
- 通过 BLE 传输 Opus，减少无线带宽占用。
- 从 macOS 将 Ogg Opus 转发到火山引擎 ASR 或 VoiceStick Cloud 中转服务。
- 松开按键并完成确认后，将最终识别文字插入 macOS 当前获得焦点的输入框。

## BLE GATT

设备名称为 `VS-XXXX`，其中 `XXXX` 来自设备 eFuse MAC 地址的最后两个字节。

服务 UUID：

```text
8f2f0b84-6e6f-4b23-88f7-3a3ceafc5100
```

特征值：

| 名称 | UUID | 方向 | 属性 |
| --- | --- | --- | --- |
| `audio_tx` | `8f2f0b84-6e6f-4b23-88f7-3a3ceafc5101` | StickS3 -> Mac | 通知（notify） |
| `state_tx` | `8f2f0b84-6e6f-4b23-88f7-3a3ceafc5102` | StickS3 -> Mac | 通知（notify） |
| `control_rx` | `8f2f0b84-6e6f-4b23-88f7-3a3ceafc5103` | Mac -> StickS3 | 无响应写入（write without response） |
| `ota_rx` | `8f2f0b84-6e6f-4b23-88f7-3a3ceafc5104` | Mac -> StickS3 | 有响应写入、无响应写入（write、write without response） |
| `ota_tx` | `8f2f0b84-6e6f-4b23-88f7-3a3ceafc5105` | StickS3 -> Mac | 通知（notify） |

桌面应用扫描此服务，只连接 `VS-XXXX` ID 已存在于本地配对列表中的设备。可同时连接多个已配对设备；音频、状态、控制及 OTA 处理均按 CoreBluetooth 外设身份区分。

## 音频帧

所有多字节字段均采用小端字节序。

```text
struct AudioBleFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x01，音频
  uint16_t header_len;    // 16
  uint32_t session_id;
  uint32_t seq;
  uint8_t  flags;         // 第 0 位表示开始，第 1 位表示结束
  uint8_t  reserved;      // 当前为 0
  uint16_t payload_len;
  uint8_t  payload[payload_len];
}
```

当 `payload_len > 0` 时，负载中包含一个原始 Opus 数据包。当前固件每包编码 60 ms、16 kHz 的单声道音频。录音停止时，固件还会发送一个满足 `flags & 0x02` 且负载为空的结束帧。

macOS 应用将接收到的 Opus 数据包封装为 Ogg Opus 流，再发送给 ASR，不会将 Opus 解码成 PCM。

## 状态事件

所有多字节字段均采用小端字节序。

```text
struct StateBleFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x10，状态
  uint16_t payload_len;
  uint8_t  json[payload_len];
}
```

状态事件由固件向应用报告设备事实，不携带“取消”或“确认”等业务动作，其含义由应用解释。

当前发送的状态事件：

```json
{"event":"device_info","hardware":"stick_s3","firmware_version":"0.2.2","buttons":["primary","secondary"],"interaction_modes":["hold_to_talk","click_to_talk"],"ui_states":["ready","recording","thinking","pending_confirmation","error"]}
{"event":"button_down","button":"primary","session_id":1234}
{"event":"button_up","button":"primary","duration_ms":620,"session_id":1234}
{"event":"button_down","button":"secondary"}
{"event":"button_up","button":"secondary","duration_ms":90}
```

按键按角色命名，而非按物理位置命名。StickS3 的正面按键对应 `primary`，侧面按键对应 `secondary`。`primary` 按键开始或结束本地录音时，事件中包含 `session_id`。

已弃用的固件到应用事件：

| 事件 | 替代方式 | 原因 |
| --- | --- | --- |
| `press_start` | 带有 `button:"primary"` 的 `button_down` | 旧名称默认指正面按键，并隐含了录音语义。 |
| `press_end` | 带有 `button:"primary"` 的 `button_up` | 旧名称隐含录音语义，且未包含按键角色。 |
| `cancel` | 带有 `button:"secondary"` 的 `button_down` / `button_up` | 旧事件混入了应用含义；根据应用状态，同一个按键可能用于取消、恢复，也可能被忽略。 |

## 控制事件

Mac 向 `control_rx` 写入紧凑 JSON。控制事件由应用向固件屏幕发送界面状态，固件以该状态为准。

当前桌面端事件：

```json
{"event":"ui_state","state":"ready","text":""}
{"event":"ui_state","state":"recording","text":""}
{"event":"ui_state","state":"thinking","text":"partial text"}
{"event":"ui_state","state":"pending_confirmation","text":"final text"}
{"event":"ui_state","state":"error","text":"ASR timeout"}
{"event":"interaction_mode","mode":"hold_to_talk"}
{"event":"interaction_mode","mode":"click_to_talk"}
```

桌面端辅助方法始终包含 `text` 字段，即使该状态没有文字内容。固件可以立即显示本地操作反馈，例如主按键开始录音时显示录音猫，但最终显示状态以应用的 `ui_state` 为准。当前 StickS3 固件的 LVGL 字体集不包含中文字形，因此不会在设备上显示识别文字；`text` 仅用于选择固定的英文提示。

`interaction_mode` 控制正面按键行为和空闲屏幕提示。`hold_to_talk` 在主按键按下时开始录音、松开时停止；`click_to_talk` 在第一次点击主按键时开始录音，下次点击时停止。

已弃用的应用到固件事件：

| 事件 | 替代方式 | 原因 |
| --- | --- | --- |
| `connected` | `ui_state:ready` | 配对后，连接本身不作为显示状态。 |
| `partial` | 带有 `text` 的 `ui_state:thinking` | 中间文字属于思考状态的显示内容。 |
| `final` | 带有 `text` 的 `ui_state:pending_confirmation` | 最终文字在粘贴前仍可取消。 |
| `paste_done` | `ui_state:ready` | 粘贴后设备恢复就绪。 |
| `paste_cancelled` | `ui_state:ready` | 取消后设备恢复就绪。 |
| `error` | 带有 `text` 的 `ui_state:error` | 错误也是一种界面状态。 |

## BLE OTA

固件在同一个 Voice Stick 服务中提供自定义 OTA 通道。macOS 应用通过 BLE 有响应写入发送 OTA `begin` 和 `end` 帧，通过无响应写入流式发送 `data` 帧，并使用 CoreBluetooth 流量控制。设备每接收约 32 KB 固件数据发送一次进度通知。

macOS 应用同一时刻只为一台已连接设备执行 OTA。应用从最新固件清单发现更新，下载清单中的 `ota_url`，校验字节大小及 SHA-256，再通过 BLE 发送已验证的应用分区镜像。浏览器烧录工具使用清单中的 `merged_url`，因为 USB 烧录会将合并镜像写入偏移地址 `0x0`。

8 MB 闪存布局包含两个 3 MB OTA 应用分区，其余空间保留为 SPIFFS 数据分区：

| 名称 | 偏移地址 | 大小 |
| --- | ---: | ---: |
| `ota_0` | `0x10000` | 3 MB |
| `ota_1` | `0x310000` | 3 MB |
| `storage` | `0x610000` | 1984 KB |

所有多字节字段均采用小端字节序。

```text
struct OtaBeginFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x20，开始
  uint16_t header_len;    // 12
  uint32_t image_size;
  uint32_t transfer_id;
}

struct OtaDataFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x21，数据
  uint16_t header_len;    // 12
  uint32_t transfer_id;
  uint32_t offset;
  uint8_t  payload[];
}

struct OtaEndFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x22，结束
  uint16_t header_len;    // 12
  uint32_t transfer_id;
  uint32_t image_size;
}

struct OtaAbortFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x23，中止
  uint16_t header_len;    // 8
  uint32_t transfer_id;
}
```

`ota_tx` 发送状态帧：

```text
struct OtaStateFrame {
  uint8_t  version;       // 1
  uint8_t  type;          // 0x30，OTA 状态
  uint16_t payload_len;
  uint8_t  json[payload_len];
}
```

OTA 状态事件包括：

```json
{"event":"ready","transfer_id":1,"size":1385760,"partition":"ota_1"}
{"event":"progress","transfer_id":1,"written":32768,"size":1385760}
{"event":"done","transfer_id":1,"reboot_ms":500}
{"event":"error","code":"bad_offset","esp_err":258}
{"event":"aborted"}
```

执行 OTA 时，设备屏幕从常规空闲 / 录音界面切换到更新状态：

- 写入镜像时显示 `Updating`（更新中）及百分比。
- 选定新的启动分区后显示 `Rebooting`（重启中）。

OTA 期间，设备忽略按键录音输入，并暂停屏幕变暗及深度睡眠计时器。传输成功后，固件发送 `done` 事件，等待约 500 ms，再调用 `esp_restart()`。桌面更新器可发送 `OtaAbortFrame` 取消正在进行的传输；设备会中止 OTA 操作，并继续使用当前固件启动。

## 运行时状态机

StickS3:

```text
boot -> advertising -> connected -> idle -> recording -> idle
```

以上状态依次表示启动、广播、已连接、空闲、录音、空闲。固件在空闲 30 秒后使屏幕变暗；电池供电时，5 分钟后进入深度睡眠；充电或 USB 供电时保持暗屏。正面按键可唤醒深度睡眠中的设备。

macOS:

```text
needs_pairing -> scanning -> ready -> recording -> thinking -> pending_confirmation -> ready
```

macOS 的上述状态依次表示需要配对、扫描、就绪、录音、思考、待确认、就绪。识别与确认期间，固件持续显示思考猫，直到应用发送 `ui_state:ready`。待确认时，`primary` 根据应用内部倒计时模式执行确认或暂停，`secondary` 执行取消。空闲时，`secondary` 恢复上一次仍可恢复的输入确认。这些含义由应用状态机决定，不属于固件协议事件本身。Windows 的侧键发送模式见 [平台说明](../desktop/windows/Windows使用说明.md#侧键确认)。

短于 0.5 秒的录音在本地丢弃，不发送给 ASR。

## ASR 传输

桌面应用可直接连接火山引擎，也可连接 VoiceStick Cloud。客户端对两者使用相同的 WebSocket 二进制帧格式，因此共用请求、音频、响应和错误处理逻辑。

火山引擎接口地址：

```text
wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async
```

VoiceStick Cloud 默认接口地址：

```text
wss://api.xiaozhi.me/voicestick/asr/
```

桌面应用当前发送的首个请求数据体为：

```json
{
  "user": {"uid": "voice-stick-local"},
  "audio": {
    "format": "ogg",
    "codec": "opus",
    "rate": 16000,
    "bits": 16,
    "channel": 1
  },
  "request": {
    "model_name": "bigmodel",
    "enable_nonstream": true,
    "show_utterances": false,
    "enable_ddc": true
  }
}
```

桌面应用先缓存 Ogg 数据块，录音达到 0.5 秒后启动 ASR，并发送已缓存的数据块。松开按键时，发送带 WebSocket 末包标记的最后一个 Ogg 数据块，再等待最终响应。

VoiceStick Cloud 业务错误应与火山引擎使用相同的错误帧格式：消息类型 `0x0f`、4 字节大端错误码、4 字节大端消息长度，以及 UTF-8 消息。配额或计费错误的消息应为 JSON，以便桌面应用展示升级入口：

```json
{
  "error": "quota_exceeded",
  "message": "Daily free quota has been used up.",
  "upgrade_url": "https://voicestick.app/account/billing"
}
```

桌面应用使用的火山引擎 API 技术细节见 [ASR 技术说明](火山引擎语音识别技术说明.md)。示例中的事件名、状态值和响应文本保留接口原值，便于与程序和日志对照。
