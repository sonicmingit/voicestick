# VoiceStick 发布流程

## Windows 中文定制版发布

本 fork 的 Windows 中文定制版使用 `windows-v<VERSION>` 标签，例如 `windows-v0.3.5`。`.github/workflows/windows-release.yml` 会从该标签构建 Windows 安装包、便携包和 StickS3 固件，并创建 GitHub Release；不需要 macOS 签名或阿里云凭据。

Windows 与固件配套更新时，`VERSION` 和 `firmware/version.txt` 必须一致。Release 包含 OTA 镜像、合并镜像、GitHub 下载地址清单和 SHA-256 校验。0.4.2 起还原样附带仓库根目录的 `VBCABLE_Driver_Pack45.zip` 和独立的豆包使用说明；客户端 MSI、便携 ZIP 均附带豆包教程，驱动由用户单独安装。此流程只发布 GitHub Release，不会覆盖阿里云 `latest/manifest.json`；需要启用客户端和网站自动发现新固件时，仍需执行下方标准发布流程中的阿里云上传。

1. 更新 `VERSION` 和 `firmware/version.txt`，并准备对应的 `docs/发布说明-Windows-<VERSION>.md`。
2. 本地可运行 `scripts/build-windows-local.ps1`；默认会编译并运行测试。
3. 提交源码与文档，推送分支，再给已提交的版本创建并推送 `windows-v<VERSION>` 标签。
4. 等待 `Windows and StickS3 Release` 工作流完成（包括 Windows 的 5 项 CTest），检查 GitHub Release 中的 MSI、ZIP、固件镜像、`manifest.json`、驱动 ZIP、`Doubao-IME-Guide.md` 和 `SHA256SUMS.txt`；下载后校验所有附件。发布目标应为该标签对应提交，并设为最新 Release。独立教程附件使用 ASCII 文件名，避免 GitHub 将纯中文名称规范化为 `default.md`，导致校验清单文件名不匹配；客户端包内仍保留中文名称。

下面的多平台发布流程保留作为上游参考。

VoiceStick 发布由三个部分组成：

- macOS 应用：由 GitHub Actions 构建、签名、公证并上传。
- StickS3 固件：由 GitHub Actions 构建，上传到阿里云 OSS 和 GitHub Releases。
- Windows 应用：在 Windows 签名机器上手动构建并签名，再上传到对应的 GitHub Release。

Windows 签名依赖本地硬件或机器上的证书配置，因此需要在本地处理。发布流程支持以下两种顺序：

- 先构建并签名 Windows 包，再由 GitHub Actions 发布 macOS 和固件。
- 先发布 macOS 和固件，之后再构建、签名并上传 Windows 包。

无论采用哪种顺序，最后都需要重新部署网站，并验证所有更新地址。

## 版本号来源

创建发布标签前，更新以下两个版本文件：

```text
VERSION
firmware/version.txt
```

桌面打包脚本和 GitHub 发布工作流使用 `VERSION`。设备上报的固件版本来自 `firmware/version.txt`，该版本必须与发布版本一致，OTA 更新检测才能正常工作。

发布版本为 `0.2.4` 时，标签必须为：

```text
v0.2.4
```

GitHub Actions 发布工作流会检查推送的标签是否与 `v<VERSION>` 一致。

## 标准流程

1. 将 `VERSION` 和 `firmware/version.txt` 更新为新版本。
2. 提交版本号变更，以及相关的发布工作流变更。
3. 推送 `main` 分支。
4. 推送发布标签：

```sh
git tag -a v0.2.4 -m "VoiceStick 0.2.4"
git push origin main
git push origin v0.2.4
```

推送标签会触发 `.github/workflows/release.yml`，该工作流构建以下文件：

- `VoiceStick-<version>.dmg`
- `VoiceStick-<version>.zip`
- `VoiceStick-<version>.signature`
- `voicestick-firmware-sticks3-ota-<version>.bin`
- `voicestick-firmware-sticks3-merged-<version>.bin`
- 固件校验和文件及 `manifest.json`

工作流还会将固件上传到阿里云 OSS 的以下两个目录：

```text
voicestick/firmwares/<version>/
voicestick/firmwares/latest/
```

GitHub Release 发布完成后，工作流触发网站部署以刷新 appcast。

## 先准备 Windows 包

在 macOS 和固件发布前就已准备好 Windows 构建及签名时，使用此流程。

1. 在 `VERSION` 中设置新版本号。
2. 在 Windows 签名机器上构建并签名 MSI：

```bat
scripts\build-msi.bat
```

输出文件为：

```text
desktop\windows\build-msi-x64\VoiceStick_<version>.msi
```

3. 确认 `firmware/version.txt` 也与新版本一致。
4. 提交变更，推送 `main`，再推送对应的 `v<version>` 标签。
5. 等待发布工作流成功完成。
6. 将已签名的 MSI 上传到同一个 GitHub Release：

```sh
gh release upload v0.2.4 desktop/windows/build-msi-x64/VoiceStick_0.2.4.msi --repo 78/voicestick
```

7. 重新运行网站部署工作流，使 appcast 包含 Windows MSI：

```sh
gh workflow run deploy-website.yml --repo 78/voicestick --ref main
```

## 先发布 macOS 和固件

如果 Windows 包尚未准备好，需要先发布 macOS 和固件，使用此流程。

1. 更新 `VERSION` 和 `firmware/version.txt`。
2. 提交变更，推送 `main`，再推送对应的 `v<version>` 标签。
3. 等待发布工作流发布 macOS 和固件。
4. 随后在 Windows 签名机器上构建并签名 MSI：

```bat
scripts\build-msi.bat
```

5. 将已签名的 MSI 上传到已经发布的 GitHub Release：

```sh
gh release upload v0.2.4 desktop/windows/build-msi-x64/VoiceStick_0.2.4.msi --repo 78/voicestick
```

6. 重新运行网站部署工作流：

```sh
gh workflow run deploy-website.yml --repo 78/voicestick --ref main
```

只有上传 MSI 并重新部署网站后，Windows 客户端才能在 appcast 中看到新的 Windows 更新。

## 发布验证

每次发布后，都要验证 appcast、固件清单和实际安装包地址。

固定的更新地址：

```text
https://78.github.io/voicestick/appcast.xml
https://xiaozhi-voice-assistant.oss-cn-shenzhen.aliyuncs.com/voicestick/firmwares/latest/manifest.json
```

以 `0.2.4` 版本为例，appcast 应包含：

```text
https://github.com/78/voicestick/releases/download/v0.2.4/VoiceStick_0.2.4.msi
https://github.com/78/voicestick/releases/download/v0.2.4/VoiceStick-0.2.4.zip
```

固件清单应包含：

```text
https://xiaozhi-voice-assistant.oss-cn-shenzhen.aliyuncs.com/voicestick/firmwares/0.2.4/voicestick-firmware-sticks3-ota-0.2.4.bin
https://xiaozhi-voice-assistant.oss-cn-shenzhen.aliyuncs.com/voicestick/firmwares/0.2.4/voicestick-firmware-sticks3-merged-0.2.4.bin
```

使用 `HEAD` 请求或浏览器确认每个地址都返回 `200`。

```powershell
Invoke-WebRequest -UseBasicParsing https://78.github.io/voicestick/appcast.xml
Invoke-WebRequest -UseBasicParsing https://xiaozhi-voice-assistant.oss-cn-shenzhen.aliyuncs.com/voicestick/firmwares/latest/manifest.json

Invoke-WebRequest -UseBasicParsing -Method Head https://github.com/78/voicestick/releases/download/v0.2.4/VoiceStick_0.2.4.msi
Invoke-WebRequest -UseBasicParsing -Method Head https://github.com/78/voicestick/releases/download/v0.2.4/VoiceStick-0.2.4.zip
Invoke-WebRequest -UseBasicParsing -Method Head https://xiaozhi-voice-assistant.oss-cn-shenzhen.aliyuncs.com/voicestick/firmwares/0.2.4/voicestick-firmware-sticks3-ota-0.2.4.bin
Invoke-WebRequest -UseBasicParsing -Method Head https://xiaozhi-voice-assistant.oss-cn-shenzhen.aliyuncs.com/voicestick/firmwares/0.2.4/voicestick-firmware-sticks3-merged-0.2.4.bin
```

同时确认以下工作流已成功运行：

- `Release Build`
- `Deploy Website to GitHub Pages`

满足以下条件时，发布才算完成：

- macOS appcast 条目指向新的 Sparkle ZIP。
- Windows appcast 条目指向新的已签名 MSI。
- 固件 `latest/manifest.json` 中的版本号已更新。
- OTA 镜像和合并固件镜像的地址均可访问。
- GitHub Release 包含完整的 macOS、Windows 和固件文件。
